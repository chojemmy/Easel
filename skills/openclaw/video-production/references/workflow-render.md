# Easel 工作流渲染与取帧规范

适用节点：Remotion 构建、样片验收、成片交付。继承同一项目已经确认的口播稿、
原片、字幕、分镜和视觉参数，不重新策划内容，也不启动整片 SDK `start/resume`。

## 先辨认当前执行阶段

- 生成视觉参数属于 Agent/模型任务；源片解码、渲染、编码和检查属于 Remotion/FFmpeg 工具任务。
- `Timeout while extracting frame ... @remotion/media` 是视频解码取帧错误，
  不能据此认定模型弱、Agent 失忆或字幕需要重写。
- 用运行日志中的真实帧号、源片秒数、退出码定位。向用户显示实际“已渲染 n/N 帧”、
  “已编码 n/N 帧”、素材准备、章节边界检查和完整解码检查，不能把工具心跳冒充完成进度。
- 退出码非零、取消、丢帧、空产物或检查失败必须停在需处理，不能标记已交付。

## 固定模板的兼容路径

1. 使用项目已安装且版本一致的 Remotion 依赖，当前固定模板为 4.0.503；不临时升级或下载浏览器。
2. Studio/Player 预览用 `@remotion/media` 的 `Video`，`objectFit` 使用独立属性。
3. 服务端导出及静帧用 `remotion` 的 `OffthreadVideo` 进行原生 FFmpeg 取帧；
   通过 `useRemotionEnvironment().isRendering` 切换组件。保留源音轨、画面比例和真实时间戳。
4. 如原片确实损坏，用 FFprobe 和 FFmpeg 在实际出错位置验证并报告。
   不通过随意加大超时、修改原片、改写转录、估算字幕时间或更换模型掩盖错误。
5. 已构建项目只有源码 SHA 与 `template-ownership.json` 一致时才可更新宿主模板；
   更新前保留旧源码。保留 `props.json`，其中视觉参数、字幕和分镜均已确认。
   发现人工源码修改时停止覆盖并如实说明。

## 样片与质量门

1. 先渲染包含实际章节转换的约 12 秒低码率样片，再做全片导出。
2. 边界静帧一次批量生成：使用已安装 CLI 的 `--frames` 非连续帧列表、`--sequence`、
   `--image-format png` 和 `--image-sequence-pattern frame-[frame].[ext]`。
   图像序列保持原片帧号，并对每个要求的帧检查文件存在且非空。
3. 每次运行使用独立输出目录；上次的样片或静帧不能替代本轮未完成的结果。
4. FFprobe 核对样片真实时长与音视频轨，FFmpeg 完整解码检查错误。
   检查报告明确列出原片时间范围、边界帧号、实际使用的解码路径及待人工验收项目。
5. 向用户展示样片和边界静帧，保留“等待确认”；用户确认后才渲染全片。
   自动检查不代表画面已由人眼验收，更不代表已发布。

## 反馈沉淀

把通用失败条件、已经验证的修复和质量检查沉淀到本仓库指南及固定执行守卫；
单条视频的稿件、视觉喜好和分镜修改仍留在该项目，避免把个案硬编码成所有视频的要求。
节点执行记录应显示实际读取的 Skill 与本指南的版本散列，不声称执行了未调用的工具。
