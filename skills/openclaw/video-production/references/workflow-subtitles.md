# Easel 工作流字幕与接续规范

本指南适用于转录节点，由项目共用的原 Easel Agent 接续执行。宿主提供本轮任务、
最新项目状态、已选主稿、校对参考与实际工具回执；它们优先于旧会话中失败的尝试。

## 原始识别

1. 有已校验的原片哈希与完整词级 ASR 缓存时复用它。修改文字、分句与风格不重跑 ASR。
2. 需要转录时，用宿主给出的 `command_argv`，项目 Python、已发现模型路径、
   CPU/int8 与 `--local-files-only`，显式输出到本次产物目录，不安装或下载另一套模型。
3. 纯文本和主稿只用于术语上下文。时间必须来自原视频/录音，不能按字数均分。
4. `transcript.json` 保留原始 ASR 的 segments、words、来源与模型，不能直接改成校对稿。
   ASR 的二三十秒长段落不能直接充当成片字幕。
5. 命令在后台返回 sessionId 时，用 `process` 等待自己启动的任务，不以“正在执行”作为最终交付。
   只有 `progress.json` 的实际阶段或工具回执才能说明转录已经开始。

## Agent 语义分句与校对

1. 读取本轮 `word-index.json`，每项为 `[id, word, start, end]`。只用实际说出的词。
2. 一条字幕是一条自然短句或完整短语，默认不超过 12 字；遵循本次明确的字数设置。
   优先在分句、主谓、并列、转折及语音停顿处分开。不能把一段长口播放在同一个时间轴，
   也不能机械每隔固定字数切一刀。字数包含英文字符及空格；不要拆英文单词、数字单位，
   专名尽量完整，超过字数的长英文短语可在单词间换句，避免语气词独占一条。
3. 句尾不保留任何标点符号。若句中有自然分界，优先拆成两条短句。
4. 用已选主稿/参考稿校正明显识别错词、专名、数字，保留实际口误；不插入录音没说过的话，
   不把口播改写成文章。不能确定的词保留原识别并在中文回执提醒抽听。
5. 用原 `write` 工具交付完整 `subtitle-plan.json`，**直接给出自然短句文字列表，不手工计算词序号**：

```json
{"lines":["第一条自然短句","第二条自然短句"],"unsupported_requests":[]}
```

所有短句合起来须完整覆盖原录音文字，不能漏词、重复、改变次序，不得拆开同一个 ASR 词。
不逐词数索引，不输出分句推演或长篇解释。宿主把文字对齐到原有词边界，生成 `from/to/text`
形式的已校验方案，再使用首尾词的真实时间；无法对齐的词或不明边界会反馈修正，绝不按字数估时。
也可以在最终正文直接交付完整 JSON。只有说明和计划不算交付。旧版明确词序号的方案仍兼容。

语义分句、句尾去标点、术语校对都是本节点支持的任务，不能列入 `unsupported_requests`。
删除音频、实际粗剪、变速或新增台词属于其他环节，须明确说明。

## 校验失败后的接续

宿主反馈哪条太长、哪些词没有覆盖或边界无效时，在同一项目会话、同一目录修正分句结果。
回执会给出具体条目、漏词和原录音上下文；一次处理列出的全部问题，不能只改第一项。
读取已有文件继续，不再运行 ASR，不新建整个转录流程，不临时编写分句脚本来替代语义判断。
不能用“准备继续”“让我执行”结束本轮，必须实际交付文件或完整 JSON，才算该阶段完成。

宿主通过后交付 `subtitles.srt`、`captions.json`、带逐句时间的 `subtitle-preview.md` 与报告。
只有真实校验回执才可以说字幕完成。用中文简要报告实际条数、参考稿、缓存复用和待抽听的词。

## 项目记忆与经验沉淀

同一视频项目的写稿、转录、分镜和制作共用一个 Agent 会话。最新 `project_memory` 包含全流程
可见对话、用户反馈、主稿和产物索引；更早历史在项目 `project.json` 中，只读查询即可。
过期、失败或尚未确认的产物不能被旧会话覆盖成“已完成”。项目修改意见先用于当前结果，
可复用的方法改进走工作台的 Skill 差异预览/应用入口，不自行覆盖共享 Skill 或记忆文件。
