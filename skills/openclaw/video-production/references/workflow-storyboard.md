# Easel 工作流分镜与素材规范

适用于“分镜与素材”节点。接续当前视频项目的统一原 Agent 会话，读取宿主提供的真实
时间轴、最新用户反馈和当前主稿。旧会话中的失败尝试、聊天操作块与未经确认的建议
不能替代本次节点产物。先读本指南，再参考 video-script 的结构规范。

## 对话与正式产物

- 在节点对话中，用中文与用户讨论方案、解释实际工具进展和接受修改意见。
- 宿主已启动正式分镜生成时，最终正文只交付一个完整 JSON 对象。可以先使用原生
  只读工具读取材料与 Skill，但最后不得附分析、说明、Markdown 围栏、easel_action
  操作块或另一次运行请求。不要套用之前节点聊天的操作格式。
- 未生成或未通过校验时，不说分镜已完成；计划与承诺不能代替产物。

## 输入与范围

1. 以 source-metadata 的实际原片时长和本次字幕时间为依据，核对原片哈希。
   当前主稿是内容参考，不能把未说出的台词补进字幕，也不能按字数猜时间。
2. 沿用用户最新确认的主线和措辞意见。用户让你自主选择示意内容时，直接给出可审查
   的方案，不反复让用户替你决定每一张卡。用户排除或未核实的说法不作为卡片卖点。
3. 本节点的固定模板保留原片画面和原声，只支持章节划分与关键文字卡。对示意图、
   B-roll、动画、粗剪的建议要与已经执行的结果区分，不能把卡片文字说成图片已生成，
   不能声称未执行的音视频删除已完成。不得启动整片 start/resume 或提前渲染。

## 分镜 JSON

仅输出以下结构，每个镜头只能有 title/start/end/purpose/card 五个字段：

```json
{"scenes":[{"title":"开场","start":0,"end":10,"purpose":"用原片建立主题","card":"网页规划，本机执行"},{"title":"展开","start":10,"end":30,"purpose":"让观众跟随实际讲解","card":""}]}
```

示例的 30 秒只演示结构，必须换成本轮原片的真实时长。具体规则：

- 1–30 个镜头，从 0 连续覆盖到实际 duration，相邻镜头前一 end 等于后一 start。
  start/end 为秒数，递增；不留空档、不重叠、不越过原片，不改速或删原声。
- title 必填且不超过 50 字；purpose 必填且不超过 250 字，说清这一段的实际画面目的。
- card 为空字符串表示不加卡片，否则最多 70 字；一个清楚的关键点，不复述整段字幕。
- 卡片总数最多 min(6, ceil(duration/20))，至少允许 1 张；只在主题、转折、关键结论或
  总结处选用，不能每句一卡。
- **相邻两个非空 card 镜头的 start 相差至少 8 秒**，不是比较镜头结束时间。
  例如上一张从 30.4 秒开始，下一张须从 38.4 秒或更晚开始；37.46 秒不合格。
- 有卡片的镜头持续至少 2 秒。不要为了通过检查虚构时间或缩短原片。
- 不输出代码、命令、URL、素材路径或其他字段；素材路径由后续实际支持的工具管理。

## 校验与修正

宿主检查 JSON、完整时间覆盖、字段、卡片数量、间隔与字数。失败时会显示具体问题，
保留本次原回复，并在同一个项目会话中最多再修正两次。只修正这份数据提议，不重新
转录、不重复执行媒体命令，不覆盖原片或其他节点材料。每次修正都交付完整 JSON，
不能只回复“已改好”或给局部片段。

通过后宿主生成 timeline.json 和可在工作台内查看的分镜预览。只有实际校验回执
才表示生成完成；分镜保持待用户确认，不自行批准、跳到渲染或发布。
