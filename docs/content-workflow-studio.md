# 内容工作流

Easel 左侧的“内容工作流”把一个视频或一篇文章保存为一个独立项目。对话仍可用于探索；制作过程、稿件、产物和确认记录在工作流中保留。

## 使用方式

1. 新建视频或文章，填写主题、受众和要求。
2. 在稿件节点添加多份手写稿、本地文本或 Obsidian 笔记，并选择唯一主稿。采用当前主稿不会自动改写；生成新稿保留原稿。
3. 视频项目导入本机原片。优先提供相应版本的 SRT、VTT 或带时间戳 JSON；文件大时直接使用本机路径。
4. 依次检查转录、确认分镜、生成画面和短样片。确认样片后才执行全片交付。
5. 发布包、平台草稿和公开发布是不同动作。正式发布有独立确认；未知结果需要到平台核实，禁止盲目重试。
6. 随时预览 Obsidian 归档，再确认存档。文章不需要经过视频节点；未发布视频也能归档。

工作流不会替用户凭空确认分镜和预览。自动检查通过只表示技术产物满足检查条件，创意与内容仍在待确认节点中审阅。

## 节点与职责

| 节点 | 输入 | 输出与确认 |
|---|---|---|
| 需求与材料 | 主题、受众、平台、风格 | 本次创作简报 |
| 口播稿 | 多份参考稿、需求、修改意见 | 选定主稿或新增生成稿 |
| 录制与导入 | 原片本机路径 | 时长、画幅、音轨、抽帧 |
| 转录与粗剪 | 原片、已有字幕或 ASR | 可核对的真实时间戳字幕；默认保留原片时间轴 |
| 分镜与素材 | 字幕、主稿、视觉需求 | 结构化分镜；确认后制作 |
| 画面制作 | 已确认分镜、模板和参数 | 独立 Remotion 工程、构建结果 |
| 预览与质检 | 制作工程 | 样片、边界静帧、检查报告；人工确认 |
| 成片与封面 | 已确认预览 | 完整视频、封面、技术验收记录 |
| 草稿与发布 | 成片、文案、平台账号 | 本地发布包或平台的实际回执 |
| Obsidian 归档 | 主稿、产物和可信发布回执 | 可预览且可追溯的归档笔记 |

## 沉淀经验

每个节点有一个范围较小的 Skill。查看标准可以读取本次运行版本与当前版本；“沉淀经验”先生成前后文本和差异，确认应用后才写入个人节点 Skill。没有确认的提议不会改变执行标准。

- 默认标准在 `easel/workflow_skills.py`，读取时不会创建共享文件。
- 个人标准位于 `$AGENT_VAULT/skills/easel-node-<节点>/SKILL.md`。不会复制或覆盖已有知识飞轮、Remotion 等共享 Skill。
- 每次运行保存实际使用的版本；个人标准变化不会悄悄覆盖旧产物。
- 可以导出一个节点或整套节点的 ZIP，包含 Skill、输入输出约定与依赖声明。个人稿件、媒体、凭证、机器路径及运行历史不随包导出。
- 可移植的是规范和接口约定。其它 Agent 仍需拥有声明的媒体工具、Remotion SDK 和对应发布适配器。

## 数据和恢复

运行数据保存在 `outputs/视频工作流/<workflow-id>/`，由 Git 忽略。`project.json` 保存稿件、版本、节点状态、运行与反馈；`artifacts/` 保存生成物和回执。

项目输入保存采用版本校验。运行时不能覆盖输入；修改稿件会使相关下游节点提示更新。仅修改发布文案不会要求重新渲染。服务重启时，运行中的节点变为中断，已有产物保留。停止仅终止本节点所属任务与子进程。

发布中断的状态为结果不明，不能自动重发。只有用户实际到平台核实“未提交”并填写记录后才解除重试限制。此操作不构成发布成功证明。

## Obsidian 归档约定

归档遵循编号、日期、标题和发布信息格式，未发布项目默认在 `3-输出/草稿`。每次先显示路径、正文和动作清单。只有当前工作流拥有且自上次归档后未被用户改动的文件才允许更新；用户修改过的文件会提示冲突。原始笔记、原片不移动、不覆盖。

只有版本匹配且验证为公开成功的发布回执，才能把归档写为已发布。上传完成、请求已提交、保存平台草稿和未知结果都不等同于已发布。媒体以链接保存，不复制大型视频进 Vault。

## 执行结构

`content_workflow.py` 负责状态与版本，`content_workflow_api.py` 提供本机 API，`workflow_runner.py` 调用受约束的工具。`workflow_archive.py` 和 `workflow_skills.py` 分别负责归档和技能版本。

创意节点通过 `workflow_model.py` 直接请求已配置模型的文本接口，不执行自由 Agent 工具循环。返回内容必须符合节点所需格式。确定性的媒体检查、SDK 调用、模板构建、渲染和发布由固定程序执行。

默认读取本机 OpenClaw 的 MiniMax 模型配置，凭证仅取环境变量。可用 `EASEL_WORKFLOW_MODEL`、`EASEL_WORKFLOW_BASE_URL`、`EASEL_WORKFLOW_API` 和 `EASEL_WORKFLOW_KEY` 配置独立模型；跨服务改地址需要显式提供对应 Key。Windows 使用既有受保护服务启动器，使密钥只进入进程环境。

## 验证

运行 `python -m pytest tests/test_content_workflow.py tests/test_workflow_archive.py tests/test_workflow_skills.py tests/test_workflow_model.py tests/test_workflow_boundaries.py`。

前端在 `web/frontend` 执行 `npm run build` 与 `npm run lint`。媒体执行器还有独立测试和真实渲染验收；测试 Vault 必须与个人 Vault 隔离。个人媒体和验收截图只保存在本地，不提交公开仓库。
